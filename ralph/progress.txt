## Codebase Patterns
- Project uses ESM (`"type": "module"`) with NodeNext module resolution
- Build with `npm run build` (tsc), typecheck with `npm run typecheck` (tsc --noEmit)
- Source in `src/`, output in `dist/`
- Shebang `#!/usr/bin/env node` on entrypoint for CLI usage
- Config types and Zod schemas live in `src/config/schema.ts` — import from there for validation and type safety
- YAML config uses hyphenated keys (`default-permission`, `hot-reload`) — access via bracket notation in TS
- Permission resolution cascades: table -> schema -> database -> `default-permission`; use `resolvePermission()` from `src/config/resolver.ts`
- `PERMISSION_HIERARCHY` in resolver.ts maps each PermissionLevel to its allowed SQL operations
- `node-sql-parser` is CJS — use `import pkg from "node-sql-parser"; const { Parser } = pkg;` for ESM compat
- `parser.tableList(sql)` returns `['operation::schema::table']` — `null` schema means unqualified (default to `public`)
- `classifyQuery()` from `src/permissions/classifier.ts` returns `{ statementType, requiredPermission, referencedTables }`
- `checkQueryPermission()` from `src/permissions/checker.ts` returns `{ allowed: true } | { allowed: false, error: McpError }` — use in tool handlers to gate execution
- MCP error shape: `{ isError: true, content: [{ type: "text", text: "..." }] }` — build via `buildPermissionError()` from `src/permissions/errors.ts`
- `pg` is CJS — use `import pg from "pg"; const { Pool } = pg;` for ESM compat
- `ConnectionManager` from `src/db/connection.ts` — use `getPool(name)` to get a pool, `addPool(name, connStr)` for runtime registration
- Introspection functions in `src/db/introspect.ts` — `getSchemas(pool)`, `getTables(pool, schema)`, `getColumns(pool, schema, table)` — all take a `pg.Pool` and query `information_schema`
- MCP server in `src/server.ts` — `createServer(config, connectionManager)` returns `McpServer`; `startServer(server)` connects stdio transport
- MCP SDK: `McpServer` from `@modelcontextprotocol/sdk/server/mcp.js`, `StdioServerTransport` from `@modelcontextprotocol/sdk/server/stdio.js`
- Register tools via `server.registerTool(name, { description, inputSchema: { param: z.string() } }, async (args, extra) => { ... })` — returns `{ content: [{ type: "text", text }] }`
- Tool return types: use `as const` for literal types in tool returns (e.g., `type: "text" as const`, `isError: true as const`)
- Tool registration pattern: export `registerXTools(server, config, connectionManager)` from `src/tools/x.ts`, call in `createServer()` in `server.ts`
- Permission filtering: use `resolvePermission()` for table-level checks, custom helpers for schema/database-level checks where no specific table is known
- `buildPermissionError()` returns `McpError` type — spread with `{ ...error }` to satisfy MCP SDK's index signature requirement in tool handlers
- `createServer(config, connectionManager, configPath?)` — pass `configPath` to enable the `register` tool for runtime DB registration
- `js-yaml.dump(config, { lineWidth: -1, quotingType: '"' })` for writing config back to YAML
- SQL tool handler pattern: (1) check db exists in config, (2) classify SQL with `classifyQuery()`, (3) reject wrong statement type, (4) `checkQueryPermission()`, (5) execute via pool, (6) return structured JSON
- `syncSchema(config, connectionManager, configPath)` from `src/db/sync.js` — reconciles config against live DB, writes updated YAML, returns `SyncSummary`
- Hot-reload in `server.ts` wraps `registerTool` before tool registration — `Object.assign(config, freshConfig)` updates the shared config reference for all tool closures
- CLI uses `commander` in `src/index.ts` — add subcommands via `program.command("name").description("...").action(...)`, call `program.parse()` at the end
- `js-yaml.dump()` doesn't support YAML comments — use raw string templates for scaffolded config files
- MCP servers must use `console.error()` for all logging — `console.log()` writes to stdout and corrupts the MCP protocol
- Config resolution in CLI: `--config` flag → `DATADAN_CONFIG` env var → `./datadan.config.yaml`
